# اسئلة الاستاذ المحتملة + اجوبة مختصرة

## قاعدة البيانات
- **اين قاعدة البيانات؟** SQLite، ملف `uniaccounts.db` يُنشأ وحده في مجلد التشغيل. الاتصال في الصنف `Database` عبر JDBC.
- **لماذا SQLite؟** لا تحتاج سيرفر ولا تثبيت، مكتبة واحدة (jar)، مناسبة لمشروع صغير.
- **ما الجداول؟** `students` (المفتاح الاساسي id) و `audit_log` (سجل التدقيق).
- **كيف تضمن ان id فريد؟** `id` هو PRIMARY KEY، والمستودع يتحقق قبل الادخال (`findById`) ويرمي `IllegalStateException`.
- **لماذا PreparedStatement؟** لتجنب SQL Injection ولان القيم تمرر كمعاملات.
- **كيف تحفظ قائمة المقررات؟** كنص واحد مفصول بـ `|` في عمود `courses`، وتُعاد بناؤها عند القراءة.
- **كيف تثبت ان البيانات محفوظة؟** شغّل `show.bat`: يقرأ القاعدة فقط بدون ادخال.
- **ما علاقة القاعدة بـ Singleton؟** `AccountRepository` نسخة وحيدة تتعامل مع القاعدة، فلا توجد مستودعات متعددة.

## Interface
- **اين Interface؟** `Prototype<T>` فيها `copy()` و`StudentAccount` ينفذها. لا توجد واجهة رسومية (GUI)، النتيجة في console.

## Builder
- لماذا الحقول الاجبارية في مُنشئ Builder؟ حتى لا تُنسى.
- ما فائدة `return this`؟ التسلسل `.level(..).major(..)`.
- اين التحقق؟ في `build()`.
- لماذا مُنشئ StudentAccount private؟ حتى لا يتجاوز احد التحقق.

## Singleton
- لماذا المُنشئ private؟ لمنع `new` من الخارج.
- لماذا Holder؟ النسخة تُنشأ عند اول طلب فقط، وآمنة مع الـ threads بدون synchronized.
- ماذا لو غاب؟ مستودعات متعددة وحسابات ضائعة وسجل مبعثر.

## Prototype
- نسخ سطحي ام عميق؟ عميق: `new ArrayList<>(courses)`.
- لماذا `phone = null` في `withIdentity`؟ حتى لا تنتقل بيانات شخصية من القالب.
- لماذا `register` يخزن `template.copy()`؟ ليبقى القالب مستقلا.

## عام
- الفرق بين Builder و Prototype؟ الاول يبني من الصفر خطوة خطوة، والثاني ينسخ كائنا جاهزا.
- لماذا هي انماط انشاء؟ لانها تجيب عن سؤال: كيف ننشئ الكائنات.
